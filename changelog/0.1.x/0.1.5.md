# 0.1.5 — 2026-06-19

## Changed

- **`fbi_get_leoka`** `deaths_by_region` output field: widened from `z.record(z.string(), z.number())` to `z.record(z.string(), z.unknown())` to accept the live nested-by-killing-type shape (`{ Felonious: { South: 31, ... }, Accidental: { ... } }`); matches the sibling `deaths_by_year` field. The `format()` region block now renders a `| Region | Felonious | Accidental |` table (regions sorted by combined total). ([#3](https://github.com/cyanheads/fbi-crime-mcp-server/issues/3))
- **`FbiLeokaChartData.officer_death_by_geographic_region`** (`src/services/fbi-api/types.ts`): `Record<string, number>` → `Record<string, Record<string, number>>`. ([#3](https://github.com/cyanheads/fbi-crime-mcp-server/issues/3))
- **Server `instructions`** (`src/index.ts`): rewritten to recommend only the three active tools (`fbi_get_crime_estimates`, `fbi_get_agency_offenses`, `fbi_get_leoka`) and state that the decommissioned surface (participation, agency search, code tables, NIBRS, arrests, hate crimes, arson, human trafficking) returns errors. No recommended call names a tool that throws `ServiceUnavailable`. ([#4](https://github.com/cyanheads/fbi-crime-mcp-server/issues/4))
- **README Resources table**: `fbi://agency/{ori}` and `fbi://state/{state_abbr}` marked `[UNAVAILABLE]` — both handlers always throw `ServiceUnavailable`. ([#4](https://github.com/cyanheads/fbi-crime-mcp-server/issues/4))

## Fixed

- **`fbi_get_leoka` SerializationError on every call** — the flat `Record<string, number>` schema rejected the live API's nested `deaths_by_region` with `Invalid input: expected number, received object`, and a flat renderer would have emitted `[object Object]` / `NaN`. Schema, type, and renderer fixed together; a regression test drives the full path (handler → `output.parse()` → `format()`) against the real nested shape. ([#3](https://github.com/cyanheads/fbi-crime-mcp-server/issues/3))

Dependency bumps:

- `@types/node` ^25.9.3 → ^25.9.4
- `vitest` ^4.1.8 → ^4.1.9
