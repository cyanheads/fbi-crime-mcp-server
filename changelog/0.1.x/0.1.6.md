# 0.1.6 — 2026-06-19

## Changed

- **`@cyanheads/mcp-ts-core` `^0.10.6` → `^0.10.8`.** Picks up: the canvas SQL gate now classifies a `SELECT`-shaped statement that parses but fails to prepare (mistyped column, unknown function) as `ValidationError` with `data.reason: 'invalid_sql'` and the DuckDB binder detail, instead of the misleading `non_select_statement` ([core #236](https://github.com/cyanheads/mcp-ts-core/issues/236)); `DuckdbProvider.describe({ tableName })` qualifies its pushed `WHERE` filters with the `t` alias, fixing the ambiguous-column Binder Error on every filtered `describe()` ([core #235](https://github.com/cyanheads/mcp-ts-core/issues/235)); the new always-present `ctx.content` collector for image/audio blocks ([core #239](https://github.com/cyanheads/mcp-ts-core/issues/239)); `biome` `2.4.16` → `2.5.0`; and `OTEL_SERVICE_NAME` documentation corrections ([core #233](https://github.com/cyanheads/mcp-ts-core/issues/233)).
- **`devcheck` scripts re-synced** to the framework's fresh-scaffold robustness guards: `scripts/build-changelog.ts` exits cleanly under `--check` when no per-version files exist ([core #242](https://github.com/cyanheads/mcp-ts-core/issues/242)); `scripts/devcheck.ts` and `scripts/check-framework-antipatterns.ts` skip the git-dependent checks (TODOs/FIXMEs, Tracked Secrets, Framework Antipatterns) via an `isGitRepo()` guard when `.git` is absent ([core #243](https://github.com/cyanheads/mcp-ts-core/issues/243)); `scripts/check-skill-versions.ts` skips a `SKILL.md` deleted from the worktree instead of crashing with ENOENT ([core #237](https://github.com/cyanheads/mcp-ts-core/issues/237)).
- **Skill re-sync** — twelve `skills/<name>/SKILL.md` updates propagated from the framework, including the seven `metadata.version` bumps that shipped pre-0.9.18 at equal versions (`api-auth`, `api-errors`, `api-services`, `api-telemetry`, `field-test`, `tool-defs-analysis`, plus `git-wrapup` v1.4 and `orchestrations` v1.4) ([core #238](https://github.com/cyanheads/mcp-ts-core/issues/238)).
- **`devcheck.config.json`** — emptied the `outdated.allowlist` (`["@cyanheads/mcp-ts-core", "@types/node"]` → `[]`); both pins are now current, so the allowlist no longer suppresses anything.

### Dependency bumps

- `@cyanheads/mcp-ts-core` ^0.10.6 → ^0.10.8
- `@types/node` ^25.9.4 → ^26.0.0
